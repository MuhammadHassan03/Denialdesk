# Denialdesk

A copilot for US medical billers. Upload 835 remittance files and EOB PDFs, and Denialdesk pulls out every denial, ranks it by dollars at stake and days left, suggests fix, appeal or write off, and drafts the corrected claim or appeal letter. Nothing leaves the app without the biller's approval.

Read [AGENTS.md](AGENTS.md) before changing anything. It holds the scope, structure and rules.

## Layout

| Folder               | What lives there                                              |
| -------------------- | ------------------------------------------------------------- |
| `apps/web`           | Next.js app: everything the biller sees                       |
| `services/pipeline`  | Python: parsing, ranking, drafting, rules checks              |
| `db/migrations`      | SQL migrations generated by Drizzle, never edited after merge |
| `fixtures/synthetic` | Fake 835s and EOBs. No real patient data, ever.               |
| `docs`               | Architecture notes and decision records                       |

## Getting started

Needs Node 24+, pnpm, uv and a local Postgres.

```
cp .env.example .env            # then fill in DATABASE_URL and PIPELINE_URL

pnpm install
pnpm dev                        # web app on localhost:3000

cd services/pipeline
uv sync
uv run fastapi dev src/denialdesk_pipeline/api.py   # pipeline API on localhost:8000
```

## Checks

Run these before calling a task done:

```
pnpm lint && pnpm typecheck && pnpm test

cd services/pipeline
uv run ruff check . && uv run mypy --strict src && uv run pytest
```

## Database

The schema lives in `apps/web/src/server/db/schema.ts`. After changing it, generate a new migration:

```
pnpm --filter @denialdesk/web db:generate
pnpm --filter @denialdesk/web db:migrate
```
